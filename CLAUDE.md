# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

This is a static artist home page for Cyjet (https://cyjet.online), displaying music releases with links to streaming platforms. There is **no build system and no package manager** — plain files are served as static assets and deployed via Cloudflare Pages (push to `main` auto-deploys).

## Current Architecture (as of the "New site design" rework)

- **`index.html`** contains the entire application: a React 18 app rendered into `<div id="root">` from one inline `<script type="text/babel">` block. React/ReactDOM are loaded as UMD **development** builds from the unpkg CDN and JSX is compiled **in the browser** by Babel Standalone. Rendering therefore requires internet access at runtime (React, Babel, Google Fonts).
- **`releases.js`** is a plain script that defines the global `MyReleases` array (loaded via `<script src="releases.js">` **before** the app script).
- **Data-driven rendering:** the app maps `MyReleases` into a component format, then renders:
  - `Hero` — the **first entry of `MyReleases` is always treated as the latest/hero release**.
  - `Tile` grid — the remaining entries (the catalogue).
  - `Drawer` — side panel opened from a tile/hero with cover, track list and platform links (Esc or backdrop closes it).
  - `App` — page layout: sticky nav, hero, catalogue grid, about, footer.
- **Platform links:** `SITE_KEY_MAP` normalises each link's `site` string to a platform key (`itunes` → `apple`, etc.; first match wins). The drawer and hero look up `r.links[platformKey]`.
- **Catalogue layout:** asymmetric CSS-grid placement generated by `buildGridLayout` — desktop 6-column and tablet 3-column row patterns with varying heights; mobile renders equal-height 2-column tiles. Breakpoints via the `useBreakpoint` hook: desktop ≥ 900px, tablet 560–899px, mobile < 560px. Styling is mostly inline `style` objects plus a small inline `<style>` block and CSS custom properties.
- **Fonts:** Space Grotesk, IBM Plex Sans, IBM Plex Mono via Google Fonts.
- **Images:** album artwork lives in `images/`, named consistently in kebab-case, e.g. `images/ep13-inland-sea-1200x1200.jpg` (pattern: `epNN-<title>-<WxH>.jpg`).

## Key Files

| File | Role |
|---|---|
| `index.html` | Page structure + the whole React app (inline `text/babel` script) + head metadata/fonts |
| `releases.js` | Release data (`MyReleases` global array) — the single source of truth for the site content |
| `releases-schema.json` | Hand-maintained JSON-LD structured data (schema.org `MusicGroup` + one `MusicAlbum` per release incl. tracks) |
| `site.webmanifest` | PWA manifest |
| `images/` | Album artwork, favicons |
| `wrangler.toml` | Cloudflare config: `assets = { directory = "." }` serves the whole repo root as static assets |
| `style.css`, `main.js` | **Legacy files from the pre-React version** (old Ramda/IIFE + CSS-grid modal design). NOT referenced by `index.html`; editing them has no effect. Candidates for removal. |

## Data Structure (`releases.js`)

Each entry in `MyReleases`:

- `artist`, `id` (e.g. `"ep17"`), `title` — basic metadata
- `cover_image` — path under `images/`
- `releaseDate` (`"2026-06"`), `releaseText` (`"june 2026"`)
- `links` — array of `{ site, href }`; `site` values seen in the data: "All sites", "Bandcamp", "Spotify", "YouTube Music", "Apple Music", "iTunes", "Amazon Music", "Deezer", "Tidal" (not every release has every platform)
- `trackList` — array of track names

## Adding a Release

1. **Prepend** a new entry to `MyReleases` at the top of `releases.js` (the first entry becomes the hero).
2. Add the artwork under `images/` and point `cover_image` at it.
3. Keep `releases-schema.json` in sync by hand (add the album + track blocks) — it lags easily; as of the EP17 entry it covers ep01–ep17.
4. Commit and push to `main`; Cloudflare Pages deploys automatically.

## Development

No build step exists. Serve the folder with any static HTTP server (e.g. `python3 -m http.server`, VS Code Live Server), then edit files directly and reload.

Caveats:

- Because JSX is compiled in-browser, a syntax error in the `text/babel` script breaks the **whole** page (no error boundary); watch DevTools console.
- External CDNs (React UMD dev builds, Babel Standalone) are large and uncompressed in dev mode; first render is slow by design today.
- Don't touch `style.css` / `main.js` for current behaviour — they are dead code from the old design.
- `releases-schema.json` is referenced from `index.html` via `<link rel="alternate" type="application/ld+json">`, which search engines do **not** parse — if structured data matters for SEO, it should be inlined as `<script type="application/ld+json">` instead.
- The grid-layout code assigns `GRID_DESKTOP`/`GRID_TABLET` before their `let` declaration (only safe because Babel downlevels `let` → `var`); keep that in mind if refactoring the layout code.
